# Revue versions et réalité du socle

Date : 6 septembre 2026. Périmètre : `ARCHITECTURE-SPINE.md`, `stack-evidence.md`, `hosting-options.md`. Vérification documentaire indépendante, sans installation, exécution du starter ni provisionnement.

**Verdict : PASS documentaire. Aucun constat bloquant.** Les versions candidates existent, les contraintes déclarées citées correspondent aux manifests éditeurs, et les documents distinguent correctement compatibilité déclarée et assemblage réellement testé.

## Résultats

- **Next 15 / React / Node : confirmé.** Le [registre Next](https://registry.npmjs.org/next) donne 15.5.25 comme dernière version stable 15, publiée le 31 août 2026. Son [manifest](https://registry.npmjs.org/next/15.5.25) accepte React `^19.0.0` et Node `>=20.0.0` parmi ses plages. Les manifests [React 19.2.8](https://registry.npmjs.org/react/19.2.8) et [React DOM 19.2.8](https://registry.npmjs.org/react-dom/19.2.8) confirment la paire. L'[index Node](https://nodejs.org/dist/index.json) confirme 24.20.0 LTS Krypton, publié le 26 août. Vercel documente [24.x géré par version majeure](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions), sans verrouillage du patch. Le [bulletin Next](https://nextjs.org/blog/august-2026-security-release) indique bien 15.5.24 comme correctif ; le candidat est postérieur.
- **Packages Supabase : confirmé.** [supabase-js 2.115.0](https://registry.npmjs.org/@supabase%2fsupabase-js/2.115.0) déclare Node >=22 ; [ssr 0.12.6](https://registry.npmjs.org/@supabase%2fssr/0.12.6) attend le SDK ^2.114.0. La [documentation de choix](https://supabase.com/docs/guides/auth/choosing-a-server-package) distingue bien sessions par cookies (`ssr`) et identité reçue par en-tête (`server`). Aucune substitution erronée n'est présente.
- **Tailwind et shadcn : confirmé.** Les manifests [Tailwind 4.3.3](https://registry.npmjs.org/tailwindcss/4.3.3), [PostCSS 4.3.3](https://registry.npmjs.org/@tailwindcss%2fpostcss/4.3.3) et [CLI shadcn 4.21.0](https://registry.npmjs.org/shadcn/4.21.0) existent. La [documentation shadcn](https://ui.shadcn.com/docs/tailwind-v4) couvre React 19/Tailwind 4. Le dossier ne confond pas version CLI et version des composants copiés.
- **Starter réel : confirmé.** Le [package.json officiel](https://raw.githubusercontent.com/vercel/next.js/canary/examples/with-supabase/package.json) conserve Next/Supabase `latest`, Tailwind ^3.4.1, types Node ^20 et eslint-config-next 15.3.1. Son [point d'entrée](https://raw.githubusercontent.com/vercel/next.js/canary/examples/with-supabase/proxy.ts) exporte `proxy`. Le [guide Next 15](https://nextjs.org/docs/15/app/api-reference/file-conventions/middleware) documente `middleware.ts` et l'export `middleware`. Le [renouvellement de session fourni](https://raw.githubusercontent.com/vercel/next.js/canary/examples/with-supabase/lib/supabase/proxy.ts) contient le contournement d'environnement décrit. L'adaptation nécessaire, y compris migration Tailwind, est donc correctement annoncée ; aucune exécution automatique prétendument conforme.
- **Services du POC : limites honnêtes.** [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp) confirme la restriction aux adresses de l'équipe sans SMTP externe. [Vercel Hobby](https://vercel.com/docs/plans/hobby) confirme la restriction d'usage personnel non commercial. Les documents ne garantissent ni gratuité ni compte déjà admissible ; aucun achat, SMTP ou service supplémentaire n'est implicitement validé. Le retrait de la sauvegarde quotidienne/sept jours est préservé.

## Observation mineure et suite requise

Les liens du starter visent `canary`, donc une source mobile. Le dossier consigne déjà un identifiant de commit et impose de figer puis relire la révision avant reprise : suffisant pour cette revue, mais les preuves du scaffold devront utiliser ses liens immuables. Le commit historique consigné n'a pas été revalidé ici ; le contenu courant vérifié correspond aux constats.

Les technologies non épinglées (notamment TypeScript, Zod, React Hook Form, CLI Supabase et primitives UI ajoutées) restent un travail explicite du scaffold, pas une compatibilité approuvée par cette revue. Vérifier alors le graphe résolu, le runtime middleware Next 15, les cookies/refresh, les politiques/RPC et les parcours réels. PostgreSQL devra être relevé sur le projet effectivement provisionné. Aucun de ces tests n'a été réalisé ou annoncé comme réussi.

Méthode : documentation officielle via navigation et manifests JSON via HTTPS/curl en lecture seule. L'accès npm par l'outil web et la chaîne de certificats de Python ayant échoué, curl avec sa vérification TLS normale a permis le contrôle ; aucune vérification TLS désactivée.
